# SG-04R Consolidated implementation roadmap

SG-04R supersedes the validation-only sequence proposed by SG-04E. The owner authorized reuse of SG-05A for Foundation and Local Authority. The SG-04E and SG-04R evidence records retain their original decisions.

## Task ID reconciliation

The active sequence begins with SG-05A, followed by SG-05C through SG-05N. SG-05B is unassigned. SG-04F0–F8 and SG-04G were unexecuted proposals. Their relevant checks now belong to the corresponding component sessions and SG-05J independent review.

## Progression rules

- Start each task when its design contract and listed prerequisites are ready; record its own lifecycle phase, task/execution/session IDs, actual model metadata, and starting Git commit.
- D01–D12 remain OPEN until their designated reviewed evidence exists. A task may implement a disabled boundary or inert model while its condition is OPEN. Keep the associated capability disabled or fail closed until the row's activation gate passes.
- Apply security controls from the first implementation change. Use TDD and independently authored expected outcomes for critical controls. Run no repository-supplied code outside verified disposable isolation.
- An unavailable runner, provider, browser, or other optional environment does not block unrelated deterministic, manual, import, schema, or documentation work.
- Existing criterion outcomes and test methods in [TEST_PLAN.md](../TEST_PLAN.md) are the acceptance oracle. No task can claim the P0 MVP complete before SG-05J passes all 53 P0 criteria, all five MVP scenarios, and applicable gates.
- Preserve P1 and P2 priorities. Regression and documentation tasks do not substitute for product acceptance.

## Genuine external prerequisites and blockers

No external infrastructure was provisioned or tested during SG-04R. Ordinary implementation work (domain types, parsers against inert fixtures, static analysis, rules, UI components, and importer/verdict code) is not blocked by an unavailable runner or provider.

Before SG-05H can activate execution, a developer/operator must identify and authorize a supported Linux host with hardware virtualization (KVM or an explicitly reviewed equivalent), disposable VM lifecycle/snapshot reset, restricted egress, no shared host credentials or writable host source mount, cgroup/resource telemetry, process-tree termination, and restart-safe recovery; provide a digest-pinned guest image and prove actual limits. SG-04E's command-name lookup did not resolve Docker, Podman, Firejail, bubblewrap, Chrome, or Edge, but it did not prove the host lacks other installations or virtualization capabilities.

Browser proof requires an approved browser installation and launch permission. Controlled provider transport proof requires an explicitly approved endpoint or controlled receiver, TLS trust material, and egress authority; no production provider is presumed. Git corpus proof needs a permitted disposable scratch repository because `.git` is read-only in the current workspace policy. Package installation and virtualization provisioning are separate future developer actions and are not assumed here.

These prerequisites apply to their dependent capabilities. Following SG-05A, the next roadmap session is **SG-05C Requirement DNA and safe Git ingestion**.
